# Iron Ridge V0.9 — Build Notes & Assumptions

This build turns the design docs in `/docs` into a playable game: a strategic hex campaign, tactical
battles on a nested sub-hex grid, and an isometric 3D view. The docs leave a lot open on purpose
("TBD", "placeholder", "pending design"). This file lists every decision made to fill those gaps,
so each one can be reviewed and changed.

Assumptions are tagged **[A#]** so you can refer to them in feedback.

---

## 1. What was built

| Area | Where |
|---|---|
| Pure TypeScript game engine (rules, grid, AI, state machine) | `packages/engine` (`@iron-ridge/engine`) |
| Isometric 3D client (three.js + React + Zustand + Tailwind) | `apps/web` |
| Engine tests (grid alignment, rules, full AI campaigns) | `packages/engine/src/*.test.ts` |
| Web tests (setup/start flow, fog-safe scene building) | `apps/web/src/**/*.test.ts(x)` |

Run it: `pnpm install && pnpm --filter @iron-ridge/web dev`, then open the Vite URL.
Tests: `pnpm turbo run test typecheck --filter=@iron-ridge/engine --filter=@iron-ridge/web`.

## 2. The grid (the key requirement)

**Requirement:** configurable grid size, and every sub-grid hex must line up with the sub-grid of
the adjacent main hex.

**How it's guaranteed.** There is only **one** sub-hex lattice for the whole world. A main hex is
not a big hexagon with small hexes inside it. It is a *hexagonal cluster of radius n* on the shared
sub-hex lattice (3n²+3n+1 cells). Radius-n clusters tile the plane exactly, using the lattice basis
`v1 = (n+1, n)` and `v2 = (−n, 2n+1)` in axial sub-hex coordinates. Its determinant, 3n²+3n+1,
equals the cluster size, so there are no gaps and no overlaps. Adjacent main hexes therefore share
real sub-hex edges, and the sub-hexes on either side of a border are ordinary neighbours on the
same grid. See `packages/engine/src/grid.ts`.

**Proven by tests** (`packages/engine/src/grid.test.ts`), for radius 1–6 and several map sizes:

- Every sub-hex has exactly one owning main hex (no gaps, no overlaps).
- Every main hex has exactly 3n²+3n+1 sub-hexes.
- The sub-hexes on both sides of every main border are direct neighbours, and the shared edge is
  the identical world-space segment seen from either side.
- Adjacent main hexes share exactly 2n+1 sub-hex edges.
- All sub-hex centres sit on one uniformly spaced lattice.

**[A1] Main hexes have jagged borders.** A perfect large hexagon cannot be tiled by small hexagons,
so the main-hex outline follows the sub-hex edges (it is drawn along those edges). This is the
geometric price of exact alignment.

**[A2] The main grid is rotated relative to the sub grid** (by the angle of `v1`, about 23–28° depending on n). The
renderer rotates the whole world by that angle so the strategic map reads left (Alpha) to right
(Bravo).

**[A3] Configurable size.** Set on the setup screen:

- Main columns: 3–12
- Main rows: 3–10
- Sub-grid radius n: 2–6 (19–127 sub-hexes per main hex)

Radius 1 (7 cells) is supported by the maths, but it is too small to deploy an 8-unit army into,
so the UI minimum is 2. The strategic map is a rectangle of main hexes in odd-r offset layout.

**[A4] Terrain is one continuous height function over sub-hex world position**, so elevation is
seamless across main borders. Heights are integers 0–8, matching the Map-01 range. Generation is
seeded:

- Plateaus on each flank.
- A central north–south ridge (H 6–8) cut by low defiles, echoing Map-01 "The Defile". Maps 9 or
  more columns wide get two ridges.
- fbm noise on top.

Each main hex's mean height is used by auto-resolve.

## 3. Two-layer loop

### Strategic layer

**[A5] Setup.**

- Alpha owns the west column of main hexes and Bravo the east column.
- Each HQ sits in the middle row.
- Each side starts with 20 CP (Command Points), one 6-unit army at HQ, and one standing
  fortification at HQ.

**[A6] Command Points** are the single currency, as the doc requires:

| Item | Amount |
|---|---|
| Income per turn | 3 + 1 per owned main hex |
| Recruiting a unit | its cost |
| Fortifying a hex | 6 CP |
| Opening a deployment (attacking) | 4 CP base + 1 CP per unit in the attacking army |

The attack cost is sunk even if the attack fails, per the "flat base + per-asset" example in the
doc.

**[A7] Armies.**

- Up to 8 units each.
- Normal move is 1 main hex per turn.
- Forced march: an army made entirely of fast units (move ≥ 5) moves 2. This is what makes surprise
  attacks possible.
- Armies moving into the same hex merge.
- Recruits appear in the HQ army; a new army is created there if none exists.

**[A8] Capture.**

- Moving into an empty non-friendly hex captures it immediately.
- Standing fortifications in a hex taken without a fight degrade by 1 level ("degrade or flip
  rather than vanish").
- Moving onto an enemy army triggers a battle.
- Win by capturing the enemy HQ. If turn 40 is reached, the side holding more hexes wins.
- A side with no armies, no money for a unit and at most one hex is eliminated.

**[A9] Warning clock.** At the start of each of the defender's turns, every owned hex with an enemy
army adjacent gains +1 warning (it resets to 0 otherwise). When that hex is attacked, the defender
gets "warned-category" sandbags:

- Count: 2 per warning turn, capped at 4.
- Placement range: within 3 MP per warning turn of the deployment zone, capped at 6. Range uses real
  terrain movement cost, as the doc specifies.

A 1-hex-per-turn army always gives at least 1 turn of warning; only forced-march armies can
achieve a true surprise. The attack axis is never revealed.

**[A10] Strategic fog.** When fog is on, enemy armies are visible only when adjacent to your
territory or your armies.

**[A11] Strategic fortify** is the commander-in-chief abstraction: you pick a hex, the engine picks
the cell.

- It first upgrades the weakest existing work ("upgrade hasty entrenchments into permanent works").
- Otherwise it builds a new level-2 work on high ground facing the nearest enemy.
- Max 6 fortified cells per hex, each up to level 3.

**[A12] Auto-resolve** (the escape valve):

- Force strength = Σ unit cost × HP%.
- Defender multiplier = 1 + min(0.6, 0.08 × fortification levels) + 0.04 × (height advantage).
- Attacker wins with probability S_att / (S_att + S_def × mult).
- Both sides bleed HP; the loser bleeds more.

### Tactical layer

**[A13] Battle map** = the contested main hex plus all its existing neighbours (up to 7 main hexes).

- The defender deploys in the contested hex; the attacker deploys in the hex it came from.
- A 2-cell no-man's-land strip along the shared border is off-limits at deployment, so battles open
  with a gap to close.
- The defender deploys first and places warned sandbags; then the attacker deploys.
- Neither side sees the other's deployment.

**[A14] Turn structure.**

- Alternating side turns ("I-go-you-go"), attacker first. Round limit is configurable 4–20
  (default 10).
- Each unit: move (spend MP), then **one action** (fire / set up / pack up / dig). Acting ends the
  unit's activation.
- Rotating facing costs 1 MP.

**[A15] Victory.**

- A side is wiped out.
- A side presses RETREAT, conceding the field (other side wins the hex).
- **Capture-point objective (default V0.9 map rule, overridable via `settings.battleObjective`):**
  the contested main-hex centre is the capture point, with radius 1. If the attacker holds that
  zone with no defenders inside it, they may **SECURE** (fortify in place — win and occupy) or
  **EXTRACT** (free pull-out to the origin deploy hex — still capture the contested hex, army
  returns to origin). This keeps unfinished fights from forcing a bloodbath while leaving the
  attacker at a disadvantage on the round-limit clock.
- The round limit is reached: the attacker wins only if it has units inside the contested hex and
  the defender has none there; otherwise the defender holds.
- Campaign turn-limit ties no longer auto-award Alpha: territory → army value → CP → draw.

**[A16] Results persist.**

- Surviving units keep their damage.
- Every fortification on the battle map (including engineer-dug ones) is written back to the
  campaign as a sub-hex-precise strategic asset.
- Defender survivors fall back to an adjacent friendly hex, or are lost if cut off.

## 4. Combat — `Iron_Ridge_Combat_Rules_v1.md`, implemented as written

The following are implemented exactly as the rules document states them:

- **§1:** base TN (heavy 7 / light 10 / unarmored 15).
- **§2:** splash TN 10 for HE weapons. Splash damages **any** unit in the radius except the
  shooter (friendly fire intentional for V0.9; future weapons may opt out).
- **§3:** range-band table per weapon profile, including tank point-blank lockout and indirect
  minimum range.
- **§4:** effective range = distance + 2 × uphill levels.
- **§5:** LOS required for direct fire; indirect fire needs a spotter, otherwise blind fire (+6, no
  splash band).
- **§6:** tank depression dead zone, max drop ⌊dist/3⌋.
- **§7:** dice pools, armor rating 0/3/6.
- **§7a:** facing modifiers (front +2/−2, rear +1/+2, side −1/0) for armored targets only.
- **§7b:** braced −2 / moved +3.

Tests cover the doc's worked examples (`rules.test.ts`).

Where the docs were silent:

**[A17] "Tiles" = sub-hexes.** Distance is hex distance.

**[A18] Natural 1 always misses, natural 20 always hits.** This keeps impossible TNs at 5% rather
than 0%.

**[A19] Damage-type matrix × dice pools.** The two docs describe damage differently: the JSON has a
qualitative effectiveness matrix, and the rules doc has dice pools and armor. They are combined:

`damage = round(roll × effectiveness) − armor ± facing` (minimum 0), with high 1.0 / medium 0.75 /
low 0.5 / none 0.

This keeps the doc's intended asymmetry: rifles do literally nothing to tanks.

**[A20] Siege vs unarmored variance** ("mostly-miss, occasional near-total-loss"). Instead of a flat
0.5, roll a d6: 1–4 → ×0.2, 5 → ×0.6, 6 → ×2.0 (catastrophic).

**[A21] LOS algorithm** (listed as "not yet designed").

- Ray-march along the hex line from the shooter's eye height (0.5–1.0 by unit) to the target's body
  height (0.5).
- Any intermediate cell whose terrain rises above the line blocks it.
- Cells outside the battle footprint (no height) also block — edge fights cannot clip through void.
- Clearance under 0.5 is **marginal**: allowed, but +2 TN, and drawn amber.
- Indirect fire uses a ballistic arc (apex 1.2 + 0.55 × distance) and can be clipped by very close,
  steep terrain.

**[A22] Vision.**

- Base vision per unit, +1 per 3 height levels of the *viewer*.
- Elevation is a **one-way** FOW advantage: high ground sees further; elevated units are not
  automatically more exposed.
- Firing reveals the shooter to the enemy until the start of the shooter's next turn; a revealed
  unit's hex also counts as spotted for friendly indirect fire.

**[A23] Cover from fortifications.** A unit on a fortified cell of level L gives attackers +L TN
(indirect: +⌊L/2⌋). Only siege direct hits reduce a fortification, by 1 level each.

**[A24] Melee (medieval), which the rules doc doesn't cover.**

- To-hit uses the point-blank band (base TN − 5).
- A surviving melee defender counter-attacks.
- Archers get a first-strike volley at anyone charging them, once per enemy turn. It is denied if
  cavalry closed 4+ cells ("speed denies volleys").
- Spearmen strike first with +3 against cavalry (braced formation).
- Cavalry get +2 damage after moving 3+ cells, except against spearmen.

**[A25] Machine-gun suppression.** An MG hit, or a near miss within 4 of the TN, suppresses an
unarmored target: half MP and +2 TN on its own attacks during its next turn.

**[A26] combat_fixed units** (MG, mortar, AT gun, artillery, catapult).

- They start the battle packed and must SET UP before firing.
- Setting up after moving uses the whole turn.
- While set up they cannot move. PACK UP costs the whole turn.

This is the doc's "braced-vs-mobile state with a pack-up cost". A strict "can never reposition"
reading felt unplayable.

**[A27] Engineers** are referenced by the core doc but absent from the units JSON, so they were
added for both eras: 8 HP, 4 CP, weak attack. DIG IN raises the fortification on the engineer's
own cell by +1 (max 3) and uses the unit's action. Engineers are ordinary soft targets while they
work.

**[A28] Tactical movement** ("real per-tile terrain cost tiers").

- Step cost = 1 + uphill levels; height-0 marsh costs +1.
- Max climb per step: infantry and cavalry 2; vehicles and artillery 1, so vehicles are funnelled
  through defiles.
- Drops of more than 4 levels are impassable.
- Units can pass through friendlies but not enemies.
- Facing becomes the direction of the last step.
- No zone of control yet (the docs list it as pending).

## 5. Unit numbers (the docs say "numeric values TBD")

Qualitative fields come verbatim from `iron-ridge-units.json`: armor class, damage type, attack
type, placement category and special rules. The engine keeps a copy, and a test fails if it drifts
from the docs file. The numbers below are **first-pass guesses for playtesting** **[A29]**:

| Unit | HP | Move | Range | Damage (direct / splash r) | CP |
|---|---|---|---|---|---|
| Rifle Infantry | 10 | 4 | 1–8 | 1d6 | 3 |
| AT Infantry | 8 | 4 | 1–5 | 2d6+2 / 1d6 | 4 |
| Machine Gun | 10 | 3 | 1–8 | 1d6+1 (suppresses) | 4 |
| Mortar | 8 | 3 | 2–10 | 2d6+1 / 2d6+1 r1 | 5 |
| Tank | 18 | 5 | 2–12 | 3d6+3 / 2d6 r1 | 10 |
| AT Gun | 12 | 2 | 1–12 | 3d6+3 / 1d6 | 6 |
| LAV | 14 | 7 | 1–8 | 2d6 | 7 |
| Artillery | 12 | 4 | 4–18 | 3d8+4 / 3d8 r1 | 9 |
| Engineers (WW2) | 8 | 4 | 1–3 | 1d4 | 4 |
| Infantry (med.) | 12 | 4 | melee | 1d6+2 | 3 |
| Archers | 8 | 4 | 2–6 | 1d6+1 | 4 |
| Horseman | 12 | 7 | melee | 1d8+1 | 5 |
| Spearman | 12 | 4 | melee | 1d6+2 | 4 |
| Catapult | 10 | 2 | 3–12 | 2d6+2 / 1d6 r1 | 7 |
| Sappers | 8 | 4 | melee | 1d4 | 4 |

Notable calls:

- **The AT gun uses the heavy-cannon pool (3d6+3)**, not the rules doc's 2d6+2. With 2d6+2 an AT gun
  needed about 7 hits to kill a tank, which broke the doc's stated balance goal (comparable
  shots-to-kill in both directions).
- **Artillery splash radius is 1**, not the doc's "2+". Radius 2 wiped whole squads on small battle
  maps.
- **Starting armies:**
  - WW2: 2× Rifle, MG, Bazooka, Tank, Engineers.
  - Medieval: 2× Infantry, Spearman, Archers, Horseman, Sappers.

## 6. Presentation

**[A30] Isometric 3D.** A true isometric orthographic camera: 35.264° elevation, 45° azimuth,
three.js.

- Each sub-hex is an extruded prism whose height is its elevation.
- Visual style is the doc's neon "training simulation": glowing height-coloured outlines, white
  main-hex borders, team-coloured territory frontiers, amber peaks, geometric unit silhouettes.
- Controls follow the doc: WASD/drag pan, Q/E rotate (45° steps), wheel zoom.
- The **F** firing view is a behind-the-unit perspective camera. The trajectory is colour-coded
  green (clear) / amber (marginal) / red (blocked).

**[A31] Modes:**

- **VS AI:** human is Alpha.
- **HOTSEAT:** two humans; with fog on, a hand-off screen appears between players.
- **AI vs AI:** spectator.

Fog of war is on by default and applies to the human's view only. The AI also plays by fog: it
only reasons about enemies it has spotted.

**[A32] Auto-save.** Every action saves to `localStorage`, and CONTINUE on the setup screen restores
it. This is best-effort; it fails silently in private mode.

**[A33] The old Express API (`apps/api`) is left untouched but unused.** V0.9 runs entirely in the
browser: the engine is pure and deterministic (seeded RNG stored in the state), so it can move
server-side later for networked multiplayer without rule changes. The old canvas prototype
components in `apps/web` were replaced.

**[A34] Sidebar panels.**

- Every sidebar panel has a collapse button.
- The battle **Selected Unit** box has a fixed height. Target and fire-control odds render in a
  reserved area inside it, so hovering never resizes anything. Logs also have fixed heights.
- Panels are always present, with placeholders when empty, so selections and AI turns don't make
  the layout jump.
- When you expand a panel and the stack overflows, other panels fold in priority order until it
  fits. The panel you just opened is never folded.
  - Battle: battle info → combat log → orders → selected unit.
  - Campaign: campaign log → hex → recruit → army → command.
- **AUTO-FOLD** at the top of the stack turns this off. FOLD ALL / OPEN ALL are there too.
- Panel state is remembered per browser.
- If folding isn't enough (small screens), only the sidebar scrolls. The map is locked to the top
  48% of the screen on mobile, or the left side on desktop, and touch drags on the map pan the
  camera instead of the page.

**[A35] Information overlays (map modes).** Terrain colouring is now one overlay at a time,
switched by the buttons at the top-left of the map or keys **1 / 2 / 3**:

- **BASIC** (default): one neutral tone. Relief comes from the 3D extrusion and lighting alone.
- **HEIGHT**: the H0–H8 elevation ramp, with a legend.
- **CONTROL**: highlights the capture point and control.
  - In battle: the capture point is orange, the attacker's staging hex is in the attacker's
    colour, and the flanking hexes are dimmed.
  - On the campaign map: hexes are tinted Alpha, Bravo or neutral.

Some things stay visible in every mode:

- Outlines with rules meaning: the capture-point outline, main-hex borders and territory
  frontiers.
- Gameplay highlights: fog dimming, move/target overlays, deployment zones and fortifications.

The choice is remembered per browser. New modes are added in `apps/web/src/render/overlays.ts`.
"Zone of control" is read here as area control around the objective. Classic wargame ZOC
(movement stopping next to enemy units) is still not implemented.

**[A36] Outlines follow the 3D terrain as connected wire chains.**

- **Terrain wireframe:** each cell draws its top outline plus a vertical line at every corner of
  each visible side face (where the neighbour is lower, or not rendered). Cliffs therefore read as
  one connected chain of lines. Where the rendered map ends, side faces are closed with a base
  outline at ground level.
- **Main-grid, capture-point and frontier outlines:**
  - Every main hex draws its own complete outline, not one shared edge per pair.
  - Each edge sits at the top of its own rendered border cell.
  - Vertical connectors join the edges wherever the height steps.
  - Lines are never lifted to a neighbour's height. Previously, out-of-play hexes just past the
    battle-map edge could leave outlines floating in mid-air.
- Tests check that every outline is a closed chain (no dangling ends), and that no battle-map edge
  sits above a rendered cell.

**[A37] Attack animations.** Each attack plays a short minimalist-geometric effect. The engine's
`AttackOutcome` now reports the origin cell, the target cell and every unit whose HP dropped
(including counters and splash). The planning lives in `apps/web/src/render/effects.ts` and the
three.js playback in `render/fx.ts`.

| Weapon | Projectile | Impact |
|---|---|---|
| Mortar, artillery, catapult | Glowing ball on a high arc | Explosion; artillery gets a bigger blast |
| Tank, AT gun, bazooka | Glowing shell in a straight line | Explosion |
| Rifle, LAV autocannon | Small bullet in a straight line | Dust puff |
| Machine gun | 3-round burst in a straight line | Dust puffs |
| Archers | Short "arrow" dash in a straight line | Dust puff |
| Melee units | None | Crossed-slash flash + ring |

- An explosion is a core flash, an expanding wireframe icosahedron, a ground hex shock ring out to
  the splash radius, and radiating line shards.
- Dust is small pale octahedron motes and a faint ring.
- Missed rounds land just off the target cell.
- Only neutral yellow, amber and orange are used. Team colours are reserved for units.
- **Damage numbers** ("-2hp", or "-9hp ✖" on a kill) rise from each damaged unit and fade.
  "MISS" or "NO EFFECT" floats over a visible target. Numbers go through fog of war, so they never
  reveal hidden enemies, and nothing is written over an empty shelled cell.
- A destroyed unit's token lingers about 1 second and shrinks away, so it is still there when the
  round lands.
- The AI waits for its shot to land before its next action.

**[A38] Action points and unit models.**

**Action points.** A unit's turn is shown as 2 action points: one **MOVE** and one **ACT**.

- Moving spends MOVE. The unit may keep using leftover MP, but the point shows as spent.
- Fire, set up, pack up or dig spends ACT. Acting ends the activation, so both points go.
- A set-up combat_fixed unit only has ACT.
- Labels read `RIF (2/2)`. The counts appear only for the side whose turn it is.
- The team-coloured glow now appears only while a unit has action points left. Spent units are
  dimmed and don't glow; the side not on turn never glows. The same rule applies on the campaign
  map: armies glow only while they have moves left.
- Logic: `actionPoints()` in `packages/engine/src/tactical.ts`.

**Unit models** (`apps/web/src/render/unitModels.ts`). Each unit type has its own model built from
chunky geometric primitives in "chibi" proportions: a big head, a short tapered body, and ball
hands sitting on the weapon.

- Weapons:
  - Rifle: the slim wedge that used to be the facing marker.
  - Machine gun: receiver, barrel and ammo box.
  - Bazooka: shoulder tube.
  - Mortar: angled tube on a base plate.
  - Engineers: a shovel and a hard hat (WW2).
  - Medieval: sword and shield, spear, bow.
- The horseman is a boxy horse with a rider and lance.
- Vehicles are short and chunky, with **cylinder barrels** on the tank, AT gun, LAV and motorized
  artillery. The catapult has a cocked throwing arm.
- **Tron look:** every structural part (body, head, hands, horse, hull, turret, treads, wheels,
  bases) is one bright, self-lit team colour, outlined with thin light edges so the shapes stay
  readable. Only the weapons differ, in neutral light metal.
- Each model turns to the unit's facing, so the separate white facing arrow is gone.

**[A39] Army commander clusters (strategic map).** An army is drawn as a small cluster: a
commander group plus up to **3 escort models**.

- **Commander:**
  - WW2: a covered truck with a gold star on the hood.
  - Medieval: a mounted commander wearing a gold crown, beside a covered horse-cart.
- **Escorts are a hybrid of the real roster and a generic group.**
  - Units are grouped into infantry, armor, artillery and cavalry.
  - Each category present gets one slot, filled by its most common type, biggest category first.
  - Leftover slots go to the next most common types, so an all-infantry army shows rifle, MG and
    bazooka rather than three rifles.
  - The token shows what the army is made of without crowding. The exact size stays in the
    "ARMY ×N" label.
- **Colour:** gold is the only accent besides weapon metal; everything else is the team colour.
- **Facing:** clusters face the enemy HQ.
- **Logic:** `armyEscorts()` and `buildArmyModel()` in `apps/web/src/render/unitModels.ts`.

## 7. Known gaps / next steps

- Supply lines and logistics, weather, zone of control, the mechanized-infantry LAV pairing, and
  towed-vs-motorized artillery. These are all marked "pending" in the docs and are not implemented.
- Cover from terrain features (forests, buildings) doesn't exist yet. Only fortifications give
  cover, per the rules doc's "open ground" note.
- AI is heuristic. It plays complete campaigns in both eras, but in AI-vs-AI testing Alpha (who
  moves first) won 5 of 6 games, so there is a first-mover edge worth tuning.
- No sound or AI narration yet (the doc's "calm synthetic-voice AI narration").
- The JS bundle is about 850 kB (mostly three.js). Code-splitting is a later optimisation.
